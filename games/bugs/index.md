# 🐞 <span class="zh">虫虫医院</span><span class="en">Bug Hospital</span>

<p class="zh">欢迎，医生！这里的每一段代码都<b>生病了</b>——里面藏着 1 到 3 只 bug（错误）。你的任务：运行它、<b>读红色的报错框</b>、找到 bug、治好它，让程序打印出和「需要的输出」一模一样的东西。治好一个病号得一颗星 ⭐。病号 7–9 是<b>重症病房</b>：bug 更安静，医院还会用秘密数据复查。</p>
<p class="en">Welcome, doctor! Every program here is <b>sick</b> — it has 1 to 3 bugs hiding inside. Your job: run it, <b>read the red error box</b>, find the bug, fix it, and make the program print exactly the "wanted output". Each patient you cure earns a star ⭐. Patients 7–9 are in the <b>intensive care ward</b>: the bugs are quieter, and the hospital re-checks with secret data.</p>

## 🩺 <span class="zh">报错怎么读</span><span class="en">How to read an error</span>

<p><span class="zh">红框会告诉你三件事。按这个顺序看：</span><span class="en">The red box tells you three things. Read them in this order:</span></p>
<ol class="code-walk">
  <li><code>🐞 第 7 行出了个小问题</code><span><span class="zh"><b>第几行</b>——先去看那一行（有时候真正的错在<b>上一行</b>）</span><span class="en"><b>Which line</b> — look there first (sometimes the real bug is on the <b>line above</b>)</span></span></li>
  <li><code>电脑看不懂这一行的写法…</code><span><span class="zh"><b>用你的话说的解释</b>——它会提醒你检查什么</span><span class="en"><b>An explanation in plain words</b> — it tells you what to check</span></span></li>
  <li><code>SyntaxError: bad input</code><span><span class="zh"><b>电脑的原话</b>——报错的<b>名字</b>（SyntaxError = 写法不对，NameError = 不认识这个名字，IndexError = 列表没这一格，TypeError = 种类搞混了）</span><span class="en"><b>What the computer said</b> — the error's <b>name</b> (SyntaxError = badly written, NameError = unknown name, IndexError = no such list item, TypeError = wrong kind of thing)</span></span></li>
</ol>
<div class="box box-good"><span class="zh">💡 一次只治一只 bug：改一点 → 运行 → 看看报错变了没有 → 再改。<b>报错变了就是进步！</b></span><span class="en">💡 Cure one bug at a time: change a little → run → did the error change? → change again. <b>A different error means progress!</b></span></div>

## 🚑 <span class="zh">重症病房：安静的 bug</span><span class="en">Intensive care: silent bugs</span>

<p class="zh">最难抓的 bug <b>不报错</b>：程序乖乖跑完，可答案是错的。这种 bug 要靠你<b>读输出、用手算、对比规则</b>来找。重症病房的病人每次运行拿到的数据都<b>不一样</b>，医院还会用<b>秘密数据</b>复查——所以只 <code>print</code> 正确答案是骗不过医生的，必须真的把程序治好。</p>
<p class="en">The hardest bugs <b>don't raise an error</b>: the program runs to the end, but the answer is wrong. You catch them by <b>reading the output, working it out by hand and comparing with the rules</b>. Patients here get <b>different data</b> every run, and the hospital re-checks them with <b>secret data</b> — so just <code>print</code>ing the right answer won't fool anyone. You have to really cure the program.</p>
<div class="box box-good"><span class="zh">🕵️ 侦探三步：① 用手算出<b>应该</b>是什么；② 看程序<b>实际</b>给了什么；③ 找到第一个不一样的地方，问「为什么」。不知道变量是多少？加一行 <code>print</code> 偷看一下！</span><span class="en">🕵️ Detective steps: ① work out by hand what it <b>should</b> be; ② see what the program <b>actually</b> gave; ③ find the first difference and ask "why?". Not sure what a variable holds? Add a <code>print</code> line to peek!</span></div>
